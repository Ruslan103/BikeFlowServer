Адреса обнаруживаются автоматически и могут быть недоступны клиенту из-за сети, NAT или настроек брандмауэра. При запуске в Docker локальный адрес контейнера может быть недоступен с других устройств — в таком случае используйте IP компьютера-хоста. Публичный IP определяется через внешний сервис api.ipify.org; для доступа из интернета также нужна настройка роутера или прокси и сертификат для используемого имени.

HTTPS и сертификат

При первом обычном запуске сервер создаёт сертификат автоматически. Действующий сертификат не заменяется без вашего действия.

Можно оставить пустым: сервер добавит localhost и своё имя. Дополнительные имена укажите через запятую.

Сетевые адреса сервера добавятся автоматически. Дополнительные IP укажите через запятую.

Файл .p12 должен содержать сертификат и закрытый ключ. Не передавайте его клиентам; клиенту нужен только публичный .crt. Сертификат, созданный при запуске, сразу используется HTTPS. Загруженный .p12 применяется после перезапуска сервера.

Сохранённые секреты не отображаются. Оставьте поле пустым, чтобы сохранить прежнее значение.

В этом режиме новое подключение будет применено при запуске обычного режима.

Изменения сохраняются по кнопке
