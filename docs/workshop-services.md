# API услуг мастерской

Все операции используют существующую авторизацию API (роль ADMIN). Для POST нужен CSRF-токен текущей сессии.

## Создание

`POST /api/services`

```json
{
  "name": "Настройка тормозов",
  "description": "Регулировка тормозной системы",
  "price": 450.00,
  "validFrom": "2026-11-06"
}
```

Название обязательно, до 150 символов. Цена обязательна, неотрицательна, до 10 цифр перед запятой и 2 после неё. Описание и validFrom необязательны; дата начала действия цены по умолчанию — текущая дата сервера.

Услуга и начальная цена сохраняются в одной транзакции. Ответ: `201 Created`, заголовок `Location: /api/services/{id}` и объект с полями `id`, `name`, `description`, `price`, `validFrom`, `validTo`.

## Чтение

- `GET /api/services` — список услуг, отсортированный по названию и ID.
- `GET /api/services/{id}` — одна услуга; неизвестный ID возвращает 404.

Чтение возвращает действующую на сегодня цену. Если действующей цены нет (например, начальная цена задана на будущее), поля `price`, `validFrom`, `validTo` будут null. Ответ создания содержит именно созданную начальную цену, включая будущую.

Ошибки валидации возвращают 400 в существующем формате ProblemDetail. Одинаковые названия допускаются, как и в текущей схеме БД. Схема БД не изменяется.
