# Поиск клиента по телефону

`GET /api/clients/search?phone=79991234567` — требуется сессия ADMIN.
При передаче номера с `+` кодируйте знак как `%2B`.

Поиск удаляет из номера форматирование, затем игнорирует **первые три цифры**
как входного номера, так и каждого сохранённого телефонного контакта.
Оставшиеся цифры должны совпадать полностью, это не поиск подстроки.
Например, `+7 (999) 123-45-67` и `+8 (119) 123-45-67` совпадают:
остаток обоих номеров — `91234567`.

Телефонным считается тип контакта с кодом `PHONE` (без учёта регистра).
Контакты других типов не участвуют в поиске, но входят в ответ.
Код PHONE должен быть назначен телефонному типу в справочнике contact_types.

Ответ — JSON-массив уникальных клиентов, отсортированных по фамилии, имени,
отчеству и ID. Каждый элемент содержит:

- `id`, `publicId`, `lastName`, `firstName`, `middleName`, `comment` — данные клиента;
- `bicycles`: `id`, `brandId`, `brandName`, `comment` — все его велосипеды;
- `contacts`: `id`, `typeId`, `typeCode`, `typeName`, `value`, `label` — все контакты.

Велосипеды и контакты сортируются по ID. Отсутствующие коллекции возвращаются
как `[]`, необязательные значения могут быть `null`. Клиент с несколькими
совпавшими телефонами возвращается один раз. Отсутствие совпадений — 200 и `[]`.

Пустой номер, менее четырёх цифр, более 255 символов или символы кроме цифр,
`+`, пробелов, скобок и дефисов — 400 в формате ProblemDetail.
Телефоны и комментарии не записываются в прикладной лог поиска.

Структура: HTTP-контроллер, DTO в `dto.client`, интерфейс и реализация в
`service.client`. Поиск выполняется в PostgreSQL; велосипеды и контакты
подгружаются двумя пакетными запросами, без отдельного запроса на каждого клиента.
