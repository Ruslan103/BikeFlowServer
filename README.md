# Craft Bike — сервер

Сервер API и личный кабинет приложения Craft Bike. Сервер написан на Spring Boot и Java 21, база данных — PostgreSQL. Рекомендуемый способ запуска — Docker Compose: он автоматически запускает сервер и базу данных, сохраняет данные между перезапусками и создаёт HTTPS-сертификат при первом запуске.

## Запуск сервера и базы данных в Docker

### Готовый пакет Docker

Для сборки релизного ZIP-пакета с Docker-образами, шаблоном `.env` и скриптами запуска выполните в PowerShell из корня репозитория:

```powershell
.\tools\build-release.ps1
```

Готовый архив появится в `dist\BikeFlowServer-1.0.1-linux-amd64.zip`. Образ рассчитан на Docker-хост `linux/amd64`; Java и Maven на хост устанавливать не нужно — Java 21 уже включена в Docker-образ. В Windows используйте `start-windows.bat`, в Linux/macOS — `sh ./start-linux.sh`. Первый запуск создаст `.env`; после заполнения паролей запустите скрипт ещё раз.

### Шаг № 1. Установите Docker

В Windows установите и запустите Docker Desktop. В Linux или macOS установите Docker Engine и плагин Docker Compose. В Windows откройте PowerShell.

### Шаг № 2. Откройте папку сервера

Перейдите в каталог `bike_server` — туда, где находятся `compose.yaml` и `.env.example`:

```powershell
cd C:\Users\zaharovra\IdeaProjects\craft_bike\bike_display\bike_server
```

### Шаг № 3. Создайте файл с паролями

Скопируйте пример и откройте файл для редактирования:

```powershell
Copy-Item .env.example .env
notepad .env
```

Замените значения-заглушки:

- `POSTGRES_PASSWORD` — длинный пароль базы данных. Используйте буквы и цифры; удобно задать случайную строку из 64 шестнадцатеричных символов.
- `BIKE_ADMIN_LOGIN` — логин администратора.
- `BIKE_ADMIN_PASSWORD` — пароль администратора длиной не менее 12 символов.
- `BIKE_TLS_DNS_NAMES` и `BIKE_TLS_IP_ADDRESSES` — адреса, по которым другие компьютеры будут подключаться к серверу.

Если сервером и клиентом пользуются только на одном компьютере, поля `BIKE_TLS_*` можно оставить пустыми: сертификат будет содержать `localhost`. Для подключения из локальной сети впишите IP-адрес сервера, например `192.168.1.20`, в `BIKE_TLS_IP_ADDRESSES`. Эти адреса нужно указать **до первого запуска**: созданный сертификат сохраняется в постоянном томе.

Не отправляйте `.env` другим людям и не добавляйте его в Git: в нём находятся пароли.

Чтобы создать случайный пароль базы в PowerShell, выполните команды ниже и скопируйте выведенную строку в `POSTGRES_PASSWORD`:

```powershell
$bytes = New-Object byte[] 32
$random = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$random.GetBytes($bytes)
[BitConverter]::ToString($bytes).Replace('-', '').ToLowerInvariant()
$random.Dispose()
```

### Шаг № 4. Соберите и запустите сервер с базой

В PowerShell, из папки `bike_server`, выполните:

```powershell
docker compose up --build -d
```

При первом запуске Docker скачает образы, соберёт сервер и создаст PostgreSQL-базу. Сервер дождётся готовности базы, создаст таблицы и подготовит HTTPS-сертификат.

### Шаг № 5. Убедитесь, что контейнеры запущены

```powershell
docker compose ps
docker compose logs -f server
```

Чтобы выйти из просмотра логов, нажмите `Ctrl+C`. Это не остановит контейнеры.

### Шаг № 6. Войдите в личный кабинет

Откройте:

- Личный кабинет: `https://localhost:8443/admin`
- Страница входа: `https://localhost:8443/login`

Войдите с логином и паролем `BIKE_ADMIN_LOGIN` и `BIKE_ADMIN_PASSWORD` из `.env`. Сервер при первом запуске создаёт учётную запись администратора.

Сертификат самоподписанный, поэтому Chrome может показать предупреждение. Для локального использования это ожидаемо, пока сертификат не добавлен в доверенные сертификаты Windows. Инструкция ниже.

### Шаг № 7. Запустите клиент CraftBiker

Если клиент уже собран, откройте последнюю папку `target\package-*\CraftBiker` в проекте `craft_biker` и запустите `CraftBiker.exe`.

Чтобы собрать клиент самостоятельно, установите JDK 21 и Maven, откройте PowerShell в папке `craft_biker` и выполните:

```powershell
cd C:\Users\zaharovra\IdeaProjects\craft_bike\bike_display\craft_biker
.\tools\build-app-image.ps1
```

Скрипт напечатает путь к новому `CraftBiker.exe` внутри `target\package-<дата-время>\CraftBiker`.

### Шаг № 8. Подключите клиент к серверу

В CraftBiker откройте **Настройки → Настройки сервера** и введите адрес сервера:

- На том же компьютере: `https://localhost:8443`
- На другом компьютере в сети: `https://<имя-или-IP-сервера>:8443`, например `https://192.168.1.20:8443`

Нажмите **Сохранить**. Клиент скачает публичный сертификат и покажет его отпечаток. Сверьте отпечаток с указанным в личном кабинете сервера и подтвердите сохранение. Кнопка **Обновить сертификат** позволяет получить его заново, не выходя из учётной записи.

Для доступа из локальной сети разрешите входящие подключения к портам `8443` и `8080` в брандмауэре компьютера-сервера. Порт `8443` обслуживает HTTPS, а `8080` используется только для первичного скачивания публичного сертификата. Порт PostgreSQL `5432` наружу не открыт.

## Доверие сертификату в браузере Windows

Эти действия нужны, если вы хотите убрать предупреждение Chrome при открытии личного кабинета. Установка сертификата в CraftBiker не меняет доверие браузера.

### Шаг № 1. Скачайте публичный сертификат

На компьютере, где работает сервер, откройте `http://localhost:8080/api/tls/certificate`. С другого компьютера используйте `http://<имя-или-IP-сервера>:8080/api/tls/certificate`. Сохранится файл сертификата `.crt`.

### Шаг № 2. Сверьте отпечаток

Войдите в личный кабинет сервера и проверьте SHA-256 отпечаток действующего сертификата в разделе **HTTPS и сертификат**. Не устанавливайте сертификат, если отпечаток не совпадает.

### Шаг № 3. Добавьте сертификат в хранилище Windows

1. Откройте скачанный `.crt` двойным щелчком.
2. Нажмите **Установить сертификат**.
3. Выберите **Текущий пользователь**.
4. Выберите **Разместить все сертификаты в следующем хранилище**.
5. Укажите **Доверенные корневые центры сертификации** и завершите мастер.
6. Перезапустите Chrome и откройте адрес сервера ещё раз.

Устанавливайте сертификат только если вы проверили его отпечаток и доверяете серверу. Для публичного сайта лучше использовать доменное имя и сертификат публичного центра сертификации.

## Управление Docker-сервером

Все команды выполняйте из папки `bike_server`.

| Действие | Команда |
| --- | --- |
| Посмотреть состояние контейнеров | `docker compose ps` |
| Смотреть логи сервера | `docker compose logs -f server` |
| Остановить сервер и базу | `docker compose stop` |
| Запустить остановленные контейнеры | `docker compose start` |
| Перезапустить только сервер | `docker compose restart server` |
| Пересобрать сервер после обновления кода | `docker compose up --build -d` |
| Удалить контейнеры, сохранив данные | `docker compose down` |

Данные PostgreSQL, настройки, сертификат и логи находятся в постоянных Docker-томах. Команда `docker compose down -v` удаляет эти тома, включая базу данных и сертификат: не используйте её, если не хотите удалить данные.

Кнопка **Перезапустить сервер** в личном кабинете перезапускает контейнер. В Docker-режиме кнопка **Выключить** подсказывает команду `docker compose stop`, потому что состоянием контейнера должен управлять Docker.

Существующая база PostgreSQL не переносится в Docker автоматически. Перед переходом сделайте резервную копию старой базы и восстановите её в контейнер PostgreSQL.

## Ручной запуск для разработки в IntelliJ IDEA

Вместо Docker можно запускать сервер и PostgreSQL отдельно на компьютере разработчика.

### Шаг № 1. Подготовьте PostgreSQL

Установите PostgreSQL и создайте пустую базу `bike_server`. Например, в pgAdmin откройте Query Tool для базы `postgres` и выполните:

```sql
CREATE DATABASE bike_server;
```

Пользователь PostgreSQL должен иметь право подключаться к `bike_server` и создавать таблицы.

### Шаг № 2. Настройте запуск режима первоначальной настройки

Откройте проект `bike_server` в IntelliJ IDEA и создайте конфигурацию типа **Application**:

- **Main class:** `com.example.demo.DemoApplication`
- **JDK:** 21
- **Working directory:** каталог проекта `bike_server`
- **Program arguments:** `--setup`
- **Environment variables:** `BIKE_ADMIN_LOGIN` и `BIKE_ADMIN_PASSWORD`

Пароль администратора должен содержать от 12 до 128 символов.

### Шаг № 3. Сохраните настройки базы

Запустите конфигурацию и откройте `http://localhost:8080/admin`. Войдите с данными из `BIKE_ADMIN_LOGIN` и `BIKE_ADMIN_PASSWORD`, укажите:

- JDBC-адрес `jdbc:postgresql://localhost:5432/bike_server`;
- логин и пароль PostgreSQL.

Сохранённые настройки появятся в `config/server-settings.properties`. Файл содержит пароль базы и не должен попадать в Git.

### Шаг № 4. Запустите обычный режим

Удалите `--setup` из **Program arguments**, оставьте переменные администратора для первого обычного запуска и перезапустите приложение. При первом обычном старте сервер создаст HTTPS-сертификат, если его ещё нет. После успешного запуска переменные `BIKE_ADMIN_LOGIN` и `BIKE_ADMIN_PASSWORD` можно удалить из конфигурации IntelliJ IDEA.

Для локального входа используйте `https://localhost:8443/login`. Публичный HTTP-порт `8080` в обычном режиме используется только для скачивания сертификата.

## Сборка и запуск сервера из JAR

Для сборки нужен JDK 21. В PowerShell из каталога `bike_server` выполните:

```powershell
.\mvnw.cmd -DskipTests package
java -jar target\demo-0.0.1-SNAPSHOT.jar
```

Для первоначальной настройки добавьте аргумент `--setup` и перед запуском задайте переменные `BIKE_ADMIN_LOGIN` и `BIKE_ADMIN_PASSWORD` в окружении процесса. Настройки базы сохраняются в `config/server-settings.properties` относительно рабочей папки.

## Где хранятся данные и что ещё важно знать

- В Docker данные PostgreSQL находятся в томе `postgres_data`; настройки и TLS-файлы — в `server_config`; логи — в `server_logs`.
- Без Docker настройки сервера хранятся в `./config/server-settings.properties`. Другой путь можно указать переменной `BIKE_SETTINGS_FILE`.
- Приложение создаёт таблицы и начальные справочные данные при запуске. В обычном режиме настройки подключения к PostgreSQL можно изменить в личном кабинете без перезапуска; после переключения базы потребуется войти снова.
- Серверные логи находятся в `logs/bike-server-application.log`; в личном кабинете отображаются последние строки журнала.
- HTTPS использует порт `8443`. Самоподписанный сертификат создаётся один раз и сохраняется. Для другого DNS-имени или IP оно должно быть записано в SAN сертификата.
- Загрузка внешнего сертификата требует файла PKCS#12 (`.p12`) с закрытым ключом и X.509 сертификатом. Файл `.p12` оставляйте на сервере; клиенту передавайте только публичный `.crt`.
- Клиент CraftBiker хранит принятое доверие к серверному сертификату отдельно от Windows и Chrome.
